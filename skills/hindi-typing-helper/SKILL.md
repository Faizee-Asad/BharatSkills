# Hindi Typing Helper

For Hindi typists, government-office staff, DTP operators, and students preparing for
Hindi typing exams (SSC, courts, CPCT/state exams, clerk and steno posts).

## First, understand the two worlds of Hindi text

**Kruti Dev (e.g. Kruti Dev 010)** — a legacy *font*, not a real encoding.
- The text is actually English letters underneath; it only *looks* like Hindi when the
  Kruti Dev font is applied. Without the font, the same text shows as garbage English
  (e.g. "gUnh" type strings).
- Uses the Remington-style typewriter layout. Still the standard in many government
  offices, courts, DTP shops and typing exams — Kruti Dev 010 is the most common one.
- Not searchable, not copy-paste friendly, and breaks on websites, mobile and email.

**Unicode Hindi (Mangal, Nirmala UI, etc.)** — the modern standard encoding.
- The text is real Hindi data: it displays correctly on any modern device, is
  searchable, works on websites, WhatsApp, forms and government portals.
- Typed with the Inscript layout, or with phonetic tools (type "bharat", get भारत).

**Golden rule:** Kruti Dev is for *typing/print workflows that demand it* (some exams,
old office files). Unicode is for *everything digital*. Most real work is converting
between the two — correctly.

## When to use this skill
- "Kruti Dev ko Unicode me badalna hai" / "Convert this Hindi text to Unicode"
- "Ye Hindi text English aksharo me dikh raha hai" (Kruti Dev text without the font)
- "Unicode wale text ko Kruti Dev me chahiye, exam/form ke liye"
- "Hindi typing exam ki taiyari kaise karu?" — which layout will the exam use?
- "Mangal font aur Kruti Dev me kya farak hai?"

## What you need from the user
- The text itself, or a description of the file (Word/Excel/PDF)
- Which direction: Kruti Dev → Unicode, or Unicode → Kruti Dev
- The purpose: exam, office document, website/form, printing/DTP
- For exam questions: which exam/body, if they know it

Never ask the user to paste the contents of a private official document into a random
online tool. If the document is sensitive (court papers, office records, exam forms),
recommend a converter that runs **entirely in the browser**, so the text never leaves
their device.

## Workflow — conversion

### 1. Identify what you actually have
- Text looks like broken English but reads as Hindi when pronounced → it is Kruti Dev
  text being shown without its font.
- Text displays as proper Hindi everywhere → it is already Unicode.
- If a Word file shows garbage, first try selecting all text and applying a Kruti Dev
  font: if it turns into readable Hindi, it was Kruti Dev all along.

### 2. Convert in the right direction
- **Kruti Dev → Unicode:** for websites, online forms, WhatsApp/email, archiving, and
  anywhere the text must be searchable.
- **Unicode → Kruti Dev:** only when a specific office, press/DTP workflow or exam
  practice setup demands a Kruti Dev file.
- Prefer a converter that runs in the browser (text stays on the user's device) —
  especially for office or legal text.

### 3. Proofread after converting — always
Converters handle normal text well, but check these known trouble spots by eye:
- Matras and half-letters: ि की placement, conjuncts like क्ष, त्र, ज्ञ, द्ध, ट्र
- Numbers: Hindi digits (१२३) vs English digits (123) — keep the style the document needs
- Punctuation, quotation marks and the danda (।)
- Names of people and places — one wrong matra changes a name on an official record

### 4. Set the font before sharing
- Unicode output → set a Unicode font (Mangal / Nirmala UI) before sending.
- Kruti Dev output → tell the receiver they need the Kruti Dev font installed, or
  share a PDF so the text cannot break on their machine.

## Workflow — typing exam preparation
1. **Find the exam's layout first.** Many government typing exams still test on
   Kruti Dev (Remington layout); others use Unicode/Inscript. The exam notice decides —
   read it and `verify before use`; practising the wrong layout wastes months.
2. **Practise in the same setup as the exam:** same layout, similar software, timed
   passages from previous papers or standard Hindi passages.
3. **Speed + accuracy both count.** Exams typically measure net speed (commonly in
   words per minute) after deducting errors — confirm the exact formula and qualifying
   speed from the current notice. `verify before use`
4. **Build accuracy first, then speed.** Daily short timed sessions beat weekend
   marathons; track WPM and error % in a simple notebook or sheet.
5. Keep a personal list of words you mistype (usually conjunct-heavy words) and drill
  those separately.

## Rules & common mistakes
- ❌ Sending Kruti Dev text by WhatsApp/email and expecting it to read as Hindi — the
  receiver sees garbage. Convert to Unicode, or send a PDF.
- ❌ Assuming converted text is perfect — matras and conjuncts must be proofread,
  especially in names on official documents.
- ❌ Mixing Kruti Dev and Unicode text in one document — it becomes uneditable and
  unsearchable. Convert the whole document to one standard.
- ❌ Keeping the only copy of an important document in Kruti Dev — archive a Unicode
  copy too; Kruti Dev text cannot be searched or reused digitally.
- ❌ Pasting sensitive office/court text into unknown converter websites — use one
  that converts in the browser so the text never leaves the device.
- ✅ When in doubt about an exam's layout, pattern or qualifying speed, say so and
  mark it `verify before use` — the official notice is the only final source.
